# Review Rubric

当任务路由是 `review` 时，默认采用“先找问题，再给结论”的口径。

## 优先级

- P0：数据丢失、安全问题、权限绕过、不可恢复破坏
- P1：功能错误、明显回归、接口不兼容、崩溃风险
- P2：可维护性风险、边界条件缺口、错误处理不足、缺测试
- P3：可读性或一致性问题

## 重点检查项

- 行为是否和需求一致
- 新旧逻辑之间是否存在回归
- 错误处理是否可操作
- 配置、环境变量、迁移步骤是否遗漏
- 测试是否覆盖改动带来的主要风险

## 输出要求

- findings 放最前面，按严重度排序
- 每条都说明：问题是什么、为什么重要、影响什么
- 尽量给出文件和行号
- 如果没有明确问题，也要说“未发现明确缺陷”，并补充剩余风险和测试盲区
