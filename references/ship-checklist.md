# Ship Checklist

进入 `ship` 路由，或准备提交 / 推送前，至少检查这些内容。

## 变更边界

- 本次 diff 是否只覆盖当前需求
- 是否混入缓存、日志、临时文件、敏感配置
- 是否需要补 `.gitignore`

## 任务与文档

- 相关 `TASKS.md` 是否已同步
- work item 是否记录了目标、验收、风险、结果
- 是否需要补充变更说明或迁移备注

## 验证

- 至少完成最小可信验证
- 若 build / 集成检查未运行，是否已说明原因
- 是否存在已知失败但尚未告知用户

## Git 动作

- `git add` 只纳入当前任务相关文件
- commit message 说明业务价值
- 未获明确要求时，不擅自 push
- push 前先确认当前分支和远端目标
